# Security Policy

Thank you for helping to keep these open-source projects secure.

## Supported versions

Security fixes are considered for the latest actively maintained release or the default branch of each project. Older releases and archived projects may not receive security updates. This is a best-effort, volunteer-maintained effort; no response or remediation deadline is guaranteed.

## Reporting a vulnerability

**Please do not open a public issue or discussion containing exploit details, credentials or other sensitive information.**

Where available, use the affected repository's **Security → Advisories → Report a vulnerability** option to submit a private report.

If private reporting is unavailable, please avoid public disclosure while seeking a suitable private contact channel. Do not post secrets or exploit details in public comments.

A useful report includes:
- The affected repository, component, commit or version
- A clear description and potential impact
- Reproduction steps or a minimal proof of concept, with sensitive data removed
- Relevant logs, screenshots or suggested mitigations, if available

## Responsible testing and disclosure

Only test systems and accounts you own or are explicitly authorised to assess. Avoid service disruption, data exfiltration, persistence and accessing third-party information.

Reports will be reviewed on a best-effort basis. Please allow time for investigation and coordination before public disclosure. Any eventual public advisory should omit live secrets and unnecessary exploitation details.

Thank you for reporting security concerns responsibly.
